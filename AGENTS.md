# Инструкции для агента

Канонический файл для Cursor. Claude Code читает те же ограничения из `CLAUDE.md` и `.claude/CLAUDE.md`.

## Что это за репозиторий

Учебный DevOps-проект для портфолио. Цель: небольшое веб-приложение на VPS с Debian 12.

Целевой контур:

- Python (FastAPI): `GET /health` и страница со счётчиком визитов.
- PostgreSQL хранит счётчик. Данные живут в Docker volume.
- Nginx принимает HTTP/HTTPS и проксирует запросы в приложение.
- Сертификат Let's Encrypt выпускает Certbot (HTTP-01, webroot).
- GitHub Actions на push в `main`: Ruff, pytest, сборка образа, публикация в GHCR, деплой по SSH.
- Секреты: `.env` на сервере и GitHub Secrets. В git только `.env.example`.

Подробности: `docs/architecture.md`, `docs/decisions/`, `docs/interview.md`.

## Как объяснять

Пользователь — junior DevOps. После каждого шага объясняй простыми словами по-русски:

1. Что появилось или изменилось.
2. Зачем это в проде.
3. Одной-двумя фразами, как это сказать на собеседовании.
4. Где это проверять: GitHub Actions или VPS. Команды Docker на рабочей станции запрещены.

Тон документов: строгий, без эмодзи, без разговорного мусора. Термин сразу сопровождай коротким смыслом.

## Жёсткие ограничения

- Не предлагай и не выполняй `docker`, `docker compose`, `podman`, `nerdctl` на компьютере разработчика. Виртуализация там недоступна.
- Не записывай секреты в репозиторий: пароли, приватные ключи, живой `.env`, содержимое `letsencrypt/`.
- Не делай force push и не переписывай историю, пока пользователь прямо об этом не попросил.
- Не помечай этап готовым, если соответствующего файла ещё нет. Карта этапов — `docs/layout.md`.
- Не создавай коммиты, пока пользователь прямо не попросил.

## Порядок работы

1. Сначала документ или правило, если меняется договорённость.
2. Затем один логический кусок: приложение, образ, compose, nginx, workflow.
3. В конце шага — как проверить этот кусок на VPS или в Actions и что считать откатом.
