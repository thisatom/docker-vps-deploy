# Как пересказать проект

Короткие ответы. Их можно говорить почти дословно. Если файла из ответа ещё нет в репозитории, так и скажи: решение принято, реализация на следующем этапе. Карта статусов — `docs/layout.md`.

## Что это за проект

Учебный деплой маленького сайта на свой VPS. Сайт считает визиты в PostgreSQL и отдаёт `/health`. Вокруг него образ, Compose, Nginx с сертификатом и pipeline в GitHub Actions.

## Почему не Kubernetes

Один сервер и три контейнера. Compose это описывает одним файлом. Kubernetes имеет смысл, когда сервисов и машин несколько. Здесь он добавил бы слова, которые нечем подтвердить.

## Зачем multi-stage Dockerfile

В первом этапе ставятся зависимости. Во второй образ копируются только код и готовые библиотеки. В проде нет компилятора и нет тестов. Образ меньше, и в нём меньше лишних программ.

## Зачем пользователь без root

Если в приложении найдут дыру, процесс внутри контейнера не будет root. Ему сложнее переписать системные файлы контейнера. Это обычная настройка, её ждут в вопросе про hardening образа.

## Зачем healthcheck у Postgres

Приложение падает или пишет ошибку, если база ещё не приняла соединения. Healthcheck говорит Compose: база готова. Сервис `app` стартует после этого условия, а не просто после создания контейнера базы.

## Где заканчивается HTTPS

На Nginx. Браузер говорит с Nginx по 443. Nginx говорит с FastAPI по HTTP внутри сети Compose. Сертификат выпускает Certbot, файлы лежат в volume.

## Где секреты

Пароль базы и почта для сертификата — в `.env` на сервере. Ключ SSH для деплоя — в GitHub Secrets. В репозитории только `.env.example` с `change-me`.

## Что делает pipeline

Каждый push запускает GitHub Actions. Сейчас job один: Ruff, затем pytest, на Python 3.12. База для этого не поднимается, тесты подменяют доступ к ней. Образ и деплой по SSH добавятся в тот же workflow, когда появятся Dockerfile и compose. Сервер сам проект собирать не будет.

## Как откатить

В `.env` на сервере меняю `APP_IMAGE` на SHA предыдущего коммита и снова делаю pull и up. Volume базы не удаляю, счётчик сохраняется.

## Как проверить, что деплой жив

С сервера или снаружи: `curl` на `/health` должен вернуть статус ok. Страница счётчика должна увеличивать число после обновления. `docker compose ps` показывает три работающих сервиса. Это проверяется на VPS. На моём компьютере Docker не запускается.

## Чего пока нельзя утверждать

Приложение, тесты и workflow с Ruff и pytest уже есть. Образа и Compose ещё нет, поэтому сайт на VPS не открывается. `/health` в тестах не ходит в базу. Живой счётчик заработает, когда на сервере появится PostgreSQL и переменная `DATABASE_URL`.
