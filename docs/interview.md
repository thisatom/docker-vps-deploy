# Как пересказать проект

Короткие ответы. Их можно говорить почти дословно. Если файла из ответа ещё нет в репозитории, так и скажи: решение принято, реализация на следующем этапе. Карта статусов — `docs/layout.md`.

## Что это за проект

Учебный деплой маленького сайта на свой VPS. Сайт считает визиты в PostgreSQL и отдаёт `/health`. Вокруг него образ, Compose, Nginx с сертификатом и pipeline в GitHub Actions.

## Почему не Kubernetes

Один сервер и три контейнера. Compose это описывает одним файлом. Kubernetes имеет смысл, когда сервисов и машин несколько. Здесь он добавил бы слова, которые нечем подтвердить.

## Зачем multi-stage Dockerfile

В этапе `build` создаётся виртуальное окружение и ставится пакет приложения без pytest и Ruff. В этап `runtime` копируется только это окружение, поэтому в проде нет компилятора и нет тестов. Пароль базы в образ не запекается: контейнер читает `DATABASE_URL` при старте. Процесс слушает порт 8000 внутри сети Compose. Наружу его откроет Nginx. Пользователь в контейнере — `app`, не root.

## Зачем пользователь без root

Если в приложении найдут дыру, процесс внутри контейнера не будет root. Ему сложнее переписать системные файлы контейнера. Это обычная настройка, её ждут в вопросе про hardening образа.

## Зачем healthcheck у Postgres

Приложение падает или пишет ошибку, если база ещё не приняла соединения. Healthcheck говорит Compose: база готова. Сервис `app` стартует после этого условия, а не просто после создания контейнера базы.

## Где заканчивается HTTPS

На Nginx. Браузер говорит с Nginx по 443. Nginx говорит с FastAPI по HTTP внутри сети Compose. Пока настоящего сертификата нет, Nginx поднимается с временным самоподписанным файлом, иначе порт 443 не открыть. В образе `nginx:1.27-alpine` нет команды `openssl`, скрипт входа ставит пакет сам и только для этого файла. Certbot методом HTTP-01 кладёт настоящий сертификат в volume. После этого контейнер Nginx пересоздают, и он читает уже файлы Let's Encrypt. Порт 80 остаётся открытым: через него проходит проверка домена, проксируется `/health`, остальное уходит редиректом на HTTPS. Продление записано в crontab два раза в сутки, потому что сертификат живёт около 90 дней.

## Где секреты

Пароль базы и почта для сертификата — в `.env` на сервере. Ключ SSH для деплоя — в GitHub Secrets. В репозитории только `.env.example` с `change-me`.

## Что делает pipeline

Каждый push и pull request запускают GitHub Actions на Python 3.12. Один job гоняет Ruff и pytest без базы: страница счётчика получает число из подмены. Второй job поднимает служебный PostgreSQL и проверяет, что счётчик растёт. Третий job на раннере собирает образ и поднимает Compose из трёх сервисов: `/health` по порту 80 и рост счётчика по HTTPS. Push в `main` после этих проверок кладёт образ в GHCR с тегом SHA и с тегом `latest`. Если в GitHub Secrets заданы `VPS_HOST`, `VPS_USER` и `VPS_SSH_KEY`, Actions по SSH заходит на VPS в `/opt/docker-vps-deploy` и запускает `deploy/update.sh`: сервер подтягивает `main` через `git pull --ff-only`, скачивает образ и поднимает контейнеры. Пока секретов нет, шаг SSH пропускается, на сервере остаётся прежний контейнер. Секреты нельзя подставлять в `if`: GitHub помечает workflow невалидным и не запускает даже тесты. Наличие секретов проверяет отдельный шаг. Сборки на сервере нет, в основном compose нет `build`. Пароль базы в Actions не передаётся.

## Как откатить

В `.env` на сервере меняю `APP_IMAGE` на SHA предыдущего коммита и запускаю `deploy/update.sh`. Скрипт подтянет текущие файлы `main`, а образ возьмёт из `.env`. Volume базы не удаляю, счётчик сохраняется. Чтобы снова принимать автоматический деплой, возвращаю тег `latest`.

## Как проверить, что деплой жив

С сервера: `curl http://127.0.0.1/health` возвращает JSON со статусом ok, порт 80 этот путь не редиректит. Страница счётчика открывается по HTTPS и увеличивает число. `docker compose ps` показывает три работающих сервиса. Это проверяется на VPS и отдельным job на раннере Actions. На моём компьютере Docker не запускается.

## Чего пока нельзя утверждать

Зелёный смоук на раннере значит, что три контейнера вместе отвечают в GitHub Actions. Он не значит, что открыт сайт на VPS. Сайт на сервере отвечает после зелёного шага SSH, когда на VPS есть `.env`, секрет SSH и git-клон в `/opt/docker-vps-deploy`. Пока секретов нет, шаг SSH пропускается. Сертификат выпускается на сервере, не на рабочей станции. Локально Compose не запускался: Docker там нет. `/health` в обычном pytest не ходит в базу.
