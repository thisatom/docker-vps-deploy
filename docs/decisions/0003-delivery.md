# 0003. Поставка и откат

## Статус

Принято. Workflow ещё не написан.

## Решение

Один workflow GitHub Actions на push в `main`:

1. Ruff.
2. pytest.
3. Сборка образа и push в `ghcr.io/<owner>/docker-vps-deploy`.
4. Тег образа — SHA коммита. Тег `latest` указывает на тот же образ.
5. По SSH на VPS выполняется `docker compose pull && docker compose up -d`.

Секреты раннера: `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY`. Пароль базы в Actions не передаётся: он уже записан в `.env` на сервере. На сервере в `.env` поле `APP_IMAGE` указывает на образ в GHCR.

Сервер исходники не компилирует. Он скачивает образ, который уже прошёл проверки.

## Откат

Образ предыдущего коммита остаётся в GHCR под своим SHA. Откат:

1. На VPS в `.env` поставить `APP_IMAGE` на предыдущий SHA.
2. `docker compose pull && docker compose up -d`.

Volume Postgres при этом не трогать. Откат приложения не должен удалять счётчик.

Если сломан сам workflow и на сервер ничего не уехало, откат не нужен: работает прежний контейнер.

## Как сказать

«Сборка отделена от сервера. В main попадает коммит, Actions гоняет линтер и тесты, кладёт образ в GHCR и по SSH просит сервер сделать pull и up. Откат — это смена тега образа на предыдущий SHA, база в volume остаётся.»
