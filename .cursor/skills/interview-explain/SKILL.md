# Объяснение для собеседования

## Когда применять

После каждого законченного шага и когда пользователь просит объяснить устройство деплоя.

## Формат ответа

Пиши по-русски, без эмодзи. Четыре коротких блока:

1. **Что сделали** — какие файлы и какое поведение.
2. **Зачем** — какую проблему это закрывает в проде.
3. **Как сказать** — 2–4 предложения разговорным, но точным языком. Без названий внутренних файлов агента.
4. **Как проверить** — GitHub Actions или команды на VPS. Команды Docker на рабочей станции не предлагай.

Опирайся на `docs/interview.md` и `docs/decisions/`. Если этап ещё не реализован, так и скажи.

## Граница

Не выдумывай, что workflow или контейнеры уже запускались. Статус этапов — в `docs/layout.md`.
